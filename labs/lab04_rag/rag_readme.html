Code Walkthrough — rag.py

A deliberately minimal RAG demo that uses raw embeddings and an LLM call, then proves where this pattern breaks.

Code Explanation
#!/usr/bin/env python3 Standard Unix shebang; lets the file be run directly as an executable from a terminal.
"""Lab 4 — RAG in about a hundred lines, then watching it fail. python rag.py "how many days annual leave do I get?" python rag.py --show-chunks "..." # see what was actually retrieved python rag.py --failures # run the three questions designed to break it There is no vector database here on purpose. A vector DB is an index and a network hop. The actual retrieval is four lines of numpy, and hiding that behind a service makes RAG seem more sophisticated than it is. """ Module docstring doubles as README: explains the pedagogical goal (show how simple—and fragile—RAG is), documents CLI usage variants, and justifies omitting a dedicated vector database to expose the core mechanics.
import argparse import os import re from pathlib import Path import anthropic import numpy as np from dotenv import load_dotenv from sentence_transformers import SentenceTransformer Imports: - argparse, os, re: CLI handling, env vars, text splitting. - pathlib.Path: filesystem helpers for locating corpus files. - anthropic: official client to call Claude models (used for generation). - numpy: used directly for similarity scoring; no extra vector DB layer. - dotenv.load_dotenv: loads environment variables from a .env file, typically for API keys.
load_dotenv() Reads .env (if present) into the process environment so secrets like ANTHROPIC_API_KEY are available without hardcoding.
MODEL = os.environ.get("WORKSHOP_MODEL", "claude-sonnet-5") CORPUS = Path(__file__).parent / "corpus" Config: - MODEL: reads an override from env; defaults to “claude-sonnet-5” (illustrative name). - CORPUS: path where markdown documents live, relative to this script’s location.
client = anthropic.Anthropic() _encoder = None Creates a persistent Anthropic client (uses env auth by default). _encoder is a module-level sentinel for lazy-loading the embedding model.
def encoder() -> SentenceTransformer: global _encoder if _encoder is None: print("Loading embedding model (first run downloads ~90MB)...") _encoder = SentenceTransformer("all-MiniLM-L6-v2") return _encoder Lazy loader for the encoder. On first call it: - Prints a heads-up that weights (~90 MB) will download on initial use. - Instantiates SentenceTransformer("all-MiniLM-L6-v2"), a small, fast model good for semantic search. Subsequent calls reuse the same instance.
def chunk_corpus() -> list[dict]: chunks = [] for path in sorted(CORPUS.glob("*.md")): text = path.read_text() for para in re.split(r"\n\s*\n", text): para = para.strip() if len(para) < 40: continue chunks.append({"source": path.name, "text": para}) return chunks Chunking strategy (intentionally simple and instructive): - Scans every .md in CORPUS. - Splits on blank-line boundaries to isolate paragraphs. - Skips very short fragments (<40 chars) to avoid noise like tiny headers. Each chunk is a dict with source (filename) and text. This naive split shows how chunking decisions directly affect what RAG can find.
def build_index(chunks: list[dict]) -> np.ndarray: vectors = encoder().encode([c["text"] for c in chunks], normalize_embeddings=True) return np.asarray(vectors) Turns every chunk into an embedding vector (L2-normalized). Storing them as a NumPy array is the “vector database”: just rows of floats. Cosine similarity then reduces to matrix multiplication.
def retrieve(query: str, chunks, index, k=3): qvec = encoder().encode([query], normalize_embeddings=True)[0] scores = index @ qvec top = np.argsort(scores)[::-1][:k] return [{**chunks[i], "score": float(scores[i])} for i in top] The retrieval core: - Embeds the query once. - scores = index @ qvec: because embeddings are normalized, this dot product is cosine similarity. - Takes the top-k chunk indices by score and returns them with their original metadata plus a numeric score.
PROMPT = """Answer the question using only the context below. If the context does not contain enough information to answer, say so explicitly rather than guessing. Context: {context} Question: {question}""" System-style prompt injected into user message: enforces “answer from context only” and encourages explicit uncertainty instead of hallucinating when evidence is missing.
def answer(question, retrieved): context = "\n\n---\n\n".join(f"[{c['source']}]\n{c['text']}" for c in retrieved) resp = client.messages.create( model=MODEL, max_tokens=600, messages=[{"role": "user", "content": PROMPT.format(context=context, question=question)}], ) return "".join(b.text for b in resp.content if b.type == "text") Generation step: - Concatenates retrieved chunks with source labels into a context block. - Sends the prompt + context + question to Claude (MODEL). - max_tokens=600 caps response length. - Joins any text content blocks from the API response.
FAILURE_QUESTIONS = [ ("multi-hop", "What notice period does a Warehouse Supervisor have to give?", "..."), ("negation", "Which roles cannot work remotely?", "..."), ("aggregation","How many separate policies mention a monetary limit, and what are they?","...")] Three handcrafted failure modes: - multi-hop: requires combining facts from different docs. - negation: relies on exclusions that embeddings don’t distinguish well. - aggregation: requires seeing the entire corpus, but top-k only returns a few chunks.
def run_failures(chunks, index, show_chunks: bool) -> None: print("\n" + "=" * 72) print("THE THREE QUESTIONS RAG IS BAD AT") ... Header for the “stress test” mode; visually separates these demos from normal questions.
for kind, question, why in FAILURE_QUESTIONS: print(f"\n\033[1m[{kind}]\033[0m {question}") retrieved = retrieve(question, chunks, index, k=3) ... Loops over each failure scenario; retrieves top-3 candidates and prints them so you can see what RAG “saw.”
print("\n\033[90mretrieved:\033[0m") for c in retrieved: preview = c["text"][:80].replace("\n", " ") print(f"\033[90m {c['score']:.3f} {c['source']:<24} {preview}...\033[0m") if show_chunks: print(f"\033[90m {c['text']}\033[0m") Prints retrieved chunks with scores and filenames. If --show-chunks is used, dumps full text to help debug why RAG succeeded or failed.
print(f"\n\033[94m{answer(question, retrieved)}\033[0m") print(f"\n\033[93mwhy this is hard: {why}\033[0m") Shows the model’s answer (in blue) then the instructor note (yellow) explaining why that question exposes RAG limitations.
if __name__ == "__main__": ap = argparse.ArgumentParser() ap.add_argument("question", nargs="?") ap.add_argument("-k", type=int, default=3, help="chunks to retrieve") ap.add_argument("--show-chunks", action="store_true") ap.add_argument("--failures", action="store_true") args = ap.parse_args() CLI definition: - question: optional positional; if omitted, a default question is used. - -k: number of chunks to retrieve (default 3). - --show-chunks: verbose mode showing full retrieved text. - --failures: run the three “known hard” questions instead.
chunks = chunk_corpus() index = build_index(chunks) print(f"Indexed {len(chunks)} chunks from {len(list(CORPUS.glob('*.md')))} documents.") On every run (for clarity), it: - Splits the corpus into chunks. - Builds the embedding index. This mirrors a real RAG startup but with no caching, emphasizing that the “vector DB” is literally just these two steps.
if args.failures: run_failures(chunks, index, args.show_chunks) If --failures is passed, bypasses a single question and runs the curated failure scenarios to demonstrate RAG’s weaknesses.
else: q = args.question or "how many days annual leave do I get?" print(f"\n\033[1mQ:\033[0m {q}\n") retrieved = retrieve(q, chunks, index, args.k) ... Normal mode: use the user’s question (or a default). Prints it, retrieves top-k chunks using configured k.
print(f"\033[90m {c['score']:.3f} {c['source']:<24} {preview}...\033[0m") if args.show_chunks: print(f"\033[90m {c['text']}\n\033[0m") print(f"\n\033[94m{answer(q, retrieved)}\033[0m\n") Prints a short preview of each retrieved chunk; full text if --show-chunks. Then calls answer() to generate the final response with Claude.
