NEEDS_APPROVAL = ["delete_file", "run_command"]
 Hard-coded allowlist of tool names that must be explicitly approved by a human before execution. This is controlled solely in this code; the model cannot override it. 
def pause(note):
    print()
    print("    " + "-" * 66)
    if PAUSE:
        input("    >>> " + note + "   (press Enter to continue) ")
    else:
        print("    >>> " + note)
    print("    " + "-" * 66)
    print()
 Utility to slow down output during demos. If PAUSE is True, blocks waiting for Enter so the operator can read what happened before continuing; otherwise just prints a banner.

task = ("Log on to the Pi, go to my home directory, find all the .tmp files "
        "and delete the largest one if there is one.")
 The user instruction given to the agent. It’s deliberately ambiguous enough that how it chooses its tools and commands becomes instructive (e.g., glob patterns, accidental deletion risk).

 Initializes the conversation history as seen by the model: one system message with instructions, one user message with the actual task. All subsequent assistant/tool messages are appended here to maintain context. 
tools = []

 Core experiment control: - Default (no flag): two narrow, well-defined tools—list files and delete a file. Easier to guard. - With --fat-tool: one generic “run shell command” schema that can do anything; harder to statically reason about safety.

 Begins the main agent loop: up to MAX_TURNS rounds. final_answer is a fallback; it will be overwritten if the model gives a proper answer before stopping. Each iteration prints a “turn” header for readability.

 Constructs the API request: - Uses entire conversation history plus available tools. - temperature=0.0 for deterministic behavior. - Disables internal “thinking”/reasoning steps to keep interaction straightforward and auditable. 
http_reply = requests.post(SERVER + "/v1/chat/completions", json=body, timeout=180)

 Sends the request to a local LLM endpoint (OpenAI-style route). raise_for_status() ensures HTTP errors crash loudly instead of being silently ignored. Response is parsed as JSON for further handling.

 - Accumulates prompt tokens to estimate context load across turns. - Extracts the model’s first (and only) completion, its message content, and why it stopped: either “stop”/“tool_calls”, etc.

 If the model outputs plain text, it’s printed. If it did not request tools (finish_reason != "tool_calls"), we treat its message as the final answer and exit: no further tool calls are needed.

else:

 The guardrail in action: if the requested tool is on the “needs approval” list (e.g., delete_file, run_command), prompt the human; otherwise proceed. This keeps fast for benign tools and cautious for risky ones. 
if not allowed:

 If the human declines: - We synthesize a tool response saying “REFUSED” and instructing the model not to retry. - This is fed back as if it were normal tool output, so the model can adapt instead of crashing or silently ignoring the refusal. 
else:
