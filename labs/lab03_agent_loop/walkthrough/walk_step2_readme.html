#!/usr/bin/env python3

# THIS CODE IS DELIBERATELY REPETITIVE. Three nearly-identical blocks.
 Purpose: Educational script demonstrating how multi-step tool-use works under the hood.
It intentionally repeats logic for each “turn” instead of abstracting it into a while-loop, so you can see exactly what happens at every step.

import pi_tools

- json: encode/decode JSON payloads.
- requests: make HTTP calls to the local server.
- pi_tools: custom module holding tool definitions and dispatch logic (e.g., list files, delete file).

- SERVER: Local endpoint running your model gateway/LLM router.

def pause(note):
    print()
    print("    " + "-" * 66)
    if PAUSE:
        input("    >>> " + note + "   (press Enter to continue) ")
    else:
        print("    >>> " + note)
    print("    " + "-" * 66)
    print()
 Utility that prints a separator and optionally blocks on user input. This makes the flow easier to follow step-by-step instead of flying by instantly. 
def ask_model(messages, tools):
    global tokens_sent_total

    body = {
        "model": "local-model",
        "messages": messages,
        "tools": tools,
        "temperature": 0.0,
        "max_tokens": 800,
        "chat_template_kwargs": {"enable_thinking": False},
        "reasoning_budget": 0,
    }
 Defines how we talk to the model:
- Sends full conversation history in messages.
- Provides available tools via tools.
- Temperature 0.0 for deterministic behavior.
- Disables internal “thinking”/reasoning chains to keep examples clean. 
    reply = requests.post(SERVER + "/v1/chat/completions", json=body, timeout=180)
    reply.raise_for_status()
    data = reply.json()

    used = data.get("usage", {}).get("prompt_tokens", 0)
    tokens_sent_total = tokens_sent_total + used
 - Sends POST request to local API.
- Raises an error if the HTTP call fails.
- Extracts usage info: specifically tracks how many prompt tokens were sent this turn and adds it into our global counter. 
    choice = data["choices"][0]
    return choice["message"], choice["finish_reason"], used
 Returns: model’s message (which may include tool calls), why it stopped, and how many tokens were used. The caller will decide whether to run tools or stop. 
def run_one_tool(tool_call):
    call_id = tool_call["id"]
    name = tool_call["function"]["name"]
    arguments = json.loads(tool_call["function"]["arguments"])

    function = pi_tools.DISPATCH.get(name)
    if function is None:
        output = "ERROR: no such tool: " + name
    else:
        output = function(**arguments)
 Executes a single requested tool:
- Reads the function name and arguments.
- Looks it up in pi_tools.DISPATCH.
- Calls that real Python function with provided arguments. This is where “the model” touches your environment via code. 
    result_message = {}
    result_message["role"] = "tool"
    result_message["tool_call_id"] = call_id
    result_message["content"] = output

    return result_message
 Builds a tool-response message in OpenAI-compatible format. The role is “tool”, and it links back via the same tool_call_id. This lets the model match outputs to its earlier requests. 
task = ("Log on to the Pi, go to my home directory, find all the .tmp files "
        "and delete the largest one if there is one.")

system_prompt = ("You are a careful assistant with access to a Raspberry Pi. "
                 "Use the tools rather than guessing...")

messages = []
messages.append({"role": "system", "content": system_prompt})
messages.append({"role": "user", "content": task})
 Sets up initial conversation:
- System prompt defines behavior and expectations.
- User message contains the actual task. These are prepended into our messages list before any turns happen. 
tools = []
tools.append(pi_tools.LIST_FILES_SCHEMA)
tools.append(pi_tools.DELETE_FILE_SCHEMA)
 Provides the model with two tool schemas (list files, delete file). These define what functions are available and their input parameters. This list is sent on every request so the model knows its options each turn.

 First API call: model sees the initial messages and available tools. It will likely decide to list files to identify any .tmp candidates. The script captures response and stop reason but discards token count here for brevity (already tracked globally). 
print("finish_reason:", repr(finish_1))

 Prints why the model stopped and any text it produced, then appends its message to history. Even if it only asked for tools (no natural-language answer), including this keeps the conversation consistent. 
for tool_call in reply_1["tool_calls"]:
    messages.append(run_one_tool(tool_call))
 For every requested tool call from the model (e.g., list_files), actually run it and append its result into the conversation as a tool message. This is how the environment’s reality is fed back in.
